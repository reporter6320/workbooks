1. What This Project Is

Scania's Complete Vehicle Acoustic team (TGRCTA1) measures how sound travels from noise sources (engine, exhaust, tyres, wind) through the truck to the driver's ear. The Air-borne Transfer Function (ATF) is the frequency-domain relationship between a source's volume velocity and sound pressure at a receiver.

You're building a toolbox that lets engineers compute, visualise, and compare ATFs from raw measurement data — replacing ad-hoc MATLAB scripts with a structured, documented, GUI-equipped tool.

2. Core Concepts

Transfer Function (FRF)
H(f) = Y(f)/X(f). In acoustics: X = volume velocity, Y = sound pressure. Captures attenuation, resonances, phase.

H1(f) = Sxy/Sxx — minimises output noise
H2(f) = Syy/Syx — minimises input noise

In a perfect measurement H1 = H2.

Coherence γ² = |Sxy|²/(Sxx·Syy). Range 0–1.

  • γ² ≈ 1 — trustworthy
  • γ² < 0.7 — suspect
  • γ² ≈ 0 — TF meaningless at that frequency

Coherence = H1/H2. Always plot it alongside the TF.

Airborne vs Structure-borne

  • Airborne: sound radiates through air from vibrating surface to receiver. ATF describes this.
  • Structure-borne: vibration enters cab through mounts; structure radiates sound inside.

TPA (Transfer Path Analysis) separates them.

Volume Velocity Q = A·v (m³/s). Natural input for airborne ATF.

Reciprocal Measurement: swap source ↔ receiver → same ATF. Validated on trucks to ±1 dB.

Spectral Estimation: FFT length (Δf = fs/N), Hanning window (50% overlap), averaging for smoother estimates.

1. What This Project Is

Scania's aftertreatment team (TGRPAEC) controls how diesel exhaust is cleaned. Centrepiece: SCR — urea (AdBlue) injected → decomposes to NH₃ → reacts with NOx on catalyst → N₂ + H₂O.

Your thesis: replace or augment the dosing controller with an ML model, validated in Software-in-the-Loop (SiL). Workflow: data prep → train → SiL integration → benchmark vs reference controller.

2. How the SCR System Works

Aftertreatment Chain:

  • DOC — oxidises CO + HC, raises temp
  • DPF — traps soot, periodically regenerated
  • SCR — the NOx reducer
  • ASC — catches excess NH₃

Chemistry: Urea → NH₃ + CO₂. NH₃ adsorbs on catalyst. Key reactions:

  • Standard SCR: 4NH₃ + 4NO + O₂ → 4N₂ + 6H₂O
  • Fast SCR: needs 1:1 NO:NO₂ — fastest
  • Slow SCR: excess NO₂ — slowest

The Core Tradeoff:

Inject more ureaInject less urea
↑ NOx conversion (good)↓ NOx conversion (fails regulation)
↑ NH₃ slip risk (bad)↓ NH₃ slip (good)
↑ AdBlue cost↓ AdBlue cost

Current Control:

  • Feedforward map: lookup by speed/load/temp → base dosing
  • Feedback: post-SCR NOx sensor (but cross-sensitive to NH₃)
  • NH₃ storage estimator: tracks stored ammonia on catalyst
  • Targets: >95% NOx conversion, <10 ppm avg NH₃ slip, <30 ppm peak
3. Software-in-the-Loop (SiL)

SiL = actual compiled ECU code on PC + simulated plant model. Plant provides sensor signals, ECU outputs actuator commands, plant responds.

V-model ladder:

  • MiL — Simulink controller + plant. Fastest.
  • SiL — compiled production code + model. Catches code bugs.
  • HiL — real ECU + real-time sim. Catches timing.
  • Vehicle — real truck. Most expensive.

Why SiL: thousands of drive cycles overnight, fair benchmark, catches integration issues MiL misses.

4. Where ML Fits
  • ML as dosing controller: replace feedforward+feedback with learned policy
  • ML as virtual sensor: predict NH₃ storage, catalyst state, outlet NOx
  • ML for catalyst model: replace physics with trained neural net
  • ML for calibration: auto-tune controller params (SwRI: weeks → hours)

Model must be small enough for ECU — export to C/ONNX.

Q: What do you know about SCR?
Urea → NH₃ → reacts with NOx on catalyst → N₂+H₂O. Tradeoff: too much = ammonia slip; too little = NOx passes through. Dosing depends on temp, flow, NOx, catalyst age, stored ammonia. Current controllers use feedforward map + NOx feedback, but calibrating across all conditions is slow — ML could help.
Q: What ML approach?
Tabular sensor inputs → start with gradient-boosted trees (fast, interpretable). Sequence modelling → LSTM or temporal CNN. Learned dosing policy → RL (harder to validate). All cases: small enough for C/ONNX, benchmark vs existing controller on same simulated cycles.
Q: What is SiL?
Compiled ECU code on PC + simulated plant. Between MiL and HiL. Thousands of cycles overnight, fair benchmark, catches code-level issues.
Q: No control background — why you?
Core deliverable is ML pipeline — data prep, model selection, rigorous benchmarking. I catch when models look good but fail on real metrics. I learn domains fast: clinical data, medical imaging, health informatics (none before KTH), NAPC paper = combustion physics from scratch.
Q: How would you validate?
Three layers: (1) ML: deterministic train/val/test splits. (2) SiL: WHTC, highway, cold start, DPF regen — compare NOx conversion, NH₃ slip, AdBlue vs reference. (3) Robustness: unseen conditions, degraded catalyst. Measure what matters (NOx under limit, slip under 10 ppm), not just RMSE.
Q: What drive cycles?
WHTC (transient, type-approval), WHSC (steady-state). Real-world: highway (high temp, easy), urban stop-go (low temp), cold start (below light-off), DPF regen (temp spike).
